## Basic Concepts (Important for Beginners)

Before jumping into the installation, let’s understand a few key concepts.

### What is VirtualBox?

VirtualBox is a virtualization tool that allows you to run multiple operating systems on a single computer.

Example:  
You can run pfSense and other operating systems inside VirtualBox without needing a separate physical machine.

---

### What is pfSense?

pfSense is an open-source firewall and router software based on FreeBSD.

It is widely used in:

- Enterprises
- Labs
- Home networks

It can:

- Filter traffic
- Act as a router
- Provide VPN services
- Monitor network activity

---

### What is a Firewall?

A firewall is a security system that:

- Monitors incoming and outgoing traffic
- Allows or blocks traffic based on rules

Think of it as a security guard for your network.

---

### What is Firewall Filtering?

Firewall filtering is the process of:

- Allowing or blocking packets based on:
  - IP address
  - Port number
  - Protocol

Example:

- Allow HTTP (port 80)
- Block unknown traffic

---

### WAN vs LAN

#### WAN (Wide Area Network)

- Represents the internet
- External network

#### LAN (Local Area Network)

- Your internal/private network
- Devices like laptops, phones

In this tutorial:

- WAN = Internet (via NAT)
- LAN = Your virtual internal network

## 5️⃣ Configure Network Adapters

This is the most important part.
In this setup, we use **two network adapters** to simulate a real-world network environment where a firewall sits between the internet and an internal network. The first adapter (Adapter 1) is set to **NAT**, which allows the virtual machine to access the internet through your host computer. NAT (Network Address Translation) works by sharing your computer’s internet connection with the virtual machine, making it behave like it is connected to an external network.

The second adapter (Adapter 2) is set to **Host-Only Adapter**, which creates a private network between your computer and the pfSense virtual machine. This acts as the internal LAN network where devices would normally connect behind a firewall.

To enable the second adapter, go to **VirtualBox → Settings → Network → Adapter 2**, check the box for **“Enable Network Adapter”**, and then select **Host-Only Adapter** from the dropdown list.

Using these two adapters allows pfSense to function properly as a firewall:

[ Internet ] → [ pfSense (WAN) ] → [ LAN Network ]

- **WAN (NAT)** → connects to the internet  
- **LAN (Host-Only)** → connects to your internal network  

This setup mimics how real networks are designed, where all internal traffic passes through a firewall before reaching the internet.

## 8️⃣ Network Configuration (Critical Step)

During the installation, pfSense will prompt you to assign network interfaces. This is a crucial step, as it determines how your firewall connects to both the internet and your internal network.
![network installation setup](/assets/img/blog2/20-pfsense-network-config-start-screen.webp)
*Figure 18: Network interface assignment screen*

### Assign Interfaces

#### WAN Interface

Select **em0** as the **WAN interface** and continue with the default settings.

**What is em0?**  
In pfSense, interfaces are named based on detected network adapters. The first adapter (Adapter 1 in VirtualBox) is typically identified as `em0`.

**Why assign em0 as WAN?**  
Since Adapter 1 is configured as **NAT**, it provides internet access. Assigning `em0` as WAN ensures pfSense can communicate with external networks (the internet).

![selecting WAN interface](/assets/img/blog2/21-pfsense-WAN-int-config-.webp)
*Figure 19: Selecting WAN interface*

![wan interface settings](/assets/img/blog2/22-pfsense-WAN-int-config-setup.webp)
*Figure 20: WAN interface settings*

#### LAN Interface

Next, select **em1** as the **LAN interface** and proceed with the default settings.

**What is em1?**  
`em1` represents the second network adapter (Adapter 2 in VirtualBox).

**Why assign em1 as LAN?**  
This adapter is configured as a **Host-Only Adapter**, which creates a private internal network. Assigning it as LAN allows you to access and manage pfSense from your host machine.

![selecting LAN interface](/assets/img/blog2/23-pfsense-LAN-int-config.webp)
*Figure 21: Selecting LAN interface*  

![lan interface settings](/assets/img/blog2/24-pfsense-WAN-int-config-setup.webp)
*Figure 22: LAN interface settings*

Make sure:

- WAN (`em0`) → connected to **NAT**
- LAN (`em1`) → connected to **Host-Only Adapter**

**Why this is important:**  
This setup mimics a real-world firewall environment where traffic flows from the internet (WAN) through the firewall to the internal network (LAN). Incorrect assignments can lead to:

- No internet access
- Inability to reach the pfSense web interface

After assigning the interfaces, pfSense will perform a connectivity check. If everything is configured correctly, the setup will proceed without errors.

![connectivity check](/assets/img/blog2/25-pfsense-network-connectivity-check.webp)
*Figure 23: Network connectivity check*

## 1️⃣1️⃣ Configure LAN IP

After rebooting, pfSense will load and display the initial console menu. This is where you perform basic configurations before accessing the web interface.
![pfSense initial configuration](/assets/img/blog2/38-reboot-vm.webp)
*Figure 36: pfSense initial console setup*

Select **Option 2: Set interface(s) IP address**.

This option allows you to manually configure the IP address of the LAN interface before accessing the web interface.

Follow the prompts:

- Choose the LAN interface when prompted and proceed with configuring its IP settings.
- Select **No** for DHCP configuration on LAN (we will configure it manually)

Set the following:

- IP Address: `192.168.56.2`
- Subnet: `24`

**Why this step matters:**  
This IP address will be used to access the pfSense web interface, so it must match the network range of your Host-Only adapter.
![LAN interface settings](/assets/img/blog2/40-assign-IPv4-address-and-subnet.webp)

**Why enable DHCP?**  
It allows devices on the network to automatically receive IP addresses, making the setup easier and more scalable.

## 1️⃣3️⃣ Access pfSense Web Interface

(43)

<https://192.168.56.2>  

After completing the basic network configuration, open a web browser on your host machine and navigate to the LAN IP address you configured earlier (e.g., `https://192.168.56.2`).  

This will take you to the pfSense web interface, which is the graphical dashboard used to manage and configure your firewall.

### Security Warning

When accessing the web interface for the first time, your browser may display a security warning. This occurs because pfSense uses a **self-signed SSL certificate** by default.

**What is a self-signed SSL certificate?**  
A self-signed certificate is an SSL certificate that is created and signed by the server itself rather than a trusted Certificate Authority (CA).

**Why is it important in real environments?**  
In production environments, SSL certificates are issued by trusted authorities to ensure secure and verified communication between users and servers.

**Why is it okay here?**  
In this lab setup, since you are accessing the firewall locally and control the environment, it is safe to proceed despite the warning.
![security warning](/assets/img/blog2/44-connection-not-secure-screen.webp)
*Figure 39: Browser security warning message*

Click on the **Advanced** button in your browser and then select **“Proceed to 192.168.56.2 (unsafe)”**.

💡 **What is happening here?**  
You are instructing your browser to trust the self-signed certificate for this session and continue to the pfSense interface. This does not pose a risk in a controlled lab environment.
![continue to web interface](/assets/img/blog2/45-conncection-not-secure-accept-and-proceed.webp)

## Common Mistakes (And How to Fix Them)

### Selecting the Wrong Architecture

- Problem: ARM64 may not work on standard systems  
- Fix: Use AMD64 (x86_64)

### LAN Interface Not Accessible

- Causes:
  - Wrong adapter type
  - Incorrect IP
- Fix:
  - Use Host-Only Adapter
  - Use IP like `192.168.56.2`

### Forgetting to Remove ISO

- Problem: System reboots into installer  
- Fix: Remove ISO before reboot

### Misconfigured Network Adapters

- Mistakes:
  - Only one adapter
  - Both set to NAT
- Fix:
  - Adapter 1 → NAT
  - Adapter 2 → Host-Only

### Browser Security Warning

- This is normal (self-signed certificate)  
- Click **Proceed**
