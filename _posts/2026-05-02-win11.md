## Installing and Configuring Windows 11 in Proxmox

In my previous blog post, I covered how to install and configure a Windows 10 virtual machine in Proxmox. In this post, I will go through the process of installing and configuring a Windows 11 virtual machine in Proxmox VE.

This guide is written for beginners who are new to virtualization, Proxmox, and Windows virtual machines. I will explain each step in detail, including the purpose of different settings and why they are important. By the end of this guide, you will have a fully functional Windows 11 VM running inside Proxmox.

## Downloading the Windows 11 ISO

Before creating the virtual machine, we first need to download the Windows 11 ISO file. Microsoft provides an official tool called the **Windows 11 Installation Media Creation Tool** which allows users to download the latest Windows 11 ISO directly from Microsoft servers.

You can download it from the official Microsoft website:

<https://www.microsoft.com/en-au/software-download/windows11>

![windows-11-media-creation-tool-download](/assets/img/blog6/1-creation-tool-download.webp)
*Figure 1: Official Windows 11 Media Creation Tool download page*

After downloading the tool, launch the setup and accept the license terms to continue.

![windows-11-media-tool-license-terms](/assets/img/blog6/2-setup-terms.webp)
*Figure 2: Windows 11 Media Creation Tool license agreement*

Next, the setup asks for the language, architecture, and edition of Windows 11. Since I am downloading the ISO for my current system, I selected the **"Use the recommended options for this PC"** option.

This automatically selects the correct Windows edition, architecture, and language based on your current system configuration.

![windows-11-edition-selection](/assets/img/blog6/3-setup-edition.webp)
*Figure 3: Selecting Windows 11 edition and architecture*

The setup then asks which media type you want to create. Since we need an ISO file for Proxmox, select **ISO file** and click **Next**.

An ISO file is essentially a digital copy of an installation DVD. Hypervisors such as Proxmox use ISO images to install operating systems into virtual machines.

![windows-11-iso-media-selection](/assets/img/blog6/4-download-media.webp)
*Figure 4: Selecting ISO file as the installation media type*

Choose a location to save the ISO file and click **Save**.

![windows-11-iso-save-location](/assets/img/blog6/5-download-location.webp)
*Figure 5: Selecting a location to save the Windows 11 ISO*

The Media Creation Tool will now begin downloading the Windows 11 installation files from Microsoft servers.

![windows-11-iso-download-progress](/assets/img/blog6/6-downloading-iso.webp)
*Figure 6: Downloading the Windows 11 ISO*

Once the download is complete, the tool verifies the downloaded files and starts creating the ISO image.

![windows-11-iso-creation-process](/assets/img/blog6/7-creating-iso.webp)
*Figure 7: Creating the Windows 11 ISO image*

After the ISO creation process is complete, the setup may ask if you want to burn the ISO file to a DVD. Since we only need the ISO file for Proxmox, simply click **Finish**.

![windows-11-iso-finished](/assets/img/blog6/8-iso-complete.webp)
*Figure 8: Windows 11 ISO creation completed*

You can now navigate to the selected download location and confirm that the ISO file was successfully created.

![windows-11-iso-file-location](/assets/img/blog6/9-download-complete.webp)
*Figure 9: Downloaded Windows 11 ISO file*

## Downloading VirtIO Drivers

Next, we need to download the VirtIO drivers ISO.

VirtIO drivers are specialized **paravirtualized** drivers used in virtual machines. Paravirtualization is a virtualization technique where the guest operating system is aware that it is running inside a virtualized environment and communicates efficiently with the hypervisor.

Without VirtIO drivers, the VM would use fully emulated hardware devices. Emulated hardware works, but it introduces additional overhead because the hypervisor must mimic real physical hardware. This results in lower performance.

VirtIO drivers solve this problem by allowing the guest operating system to communicate more directly and efficiently with the hypervisor. This improves:

- Disk performance
- Network performance
- Memory efficiency
- Overall VM responsiveness

In Proxmox, VirtIO drivers are especially important for Windows virtual machines because Windows does not include these drivers by default.

You can download the VirtIO driver ISO from the following link:

<https://fedorapeople.org/groups/virt/virtio-win/direct-downloads/archive-virtio/virtio-win-0.1.262-2/>

![virtio-driver-download-page](/assets/img/blog6/11-download-virtIO.webp)
*Figure 10: Downloading the VirtIO driver ISO*

## Uploading ISO Files to Proxmox

Now that both ISO files are downloaded, we need to upload them into Proxmox.

Proxmox stores ISO images inside a dedicated storage location called an **ISO image library**. Keeping ISO files in a centralized storage location makes VM management easier because multiple virtual machines can access the same installation media.

This approach also improves organization and prevents duplication of files across different virtual machines.

Navigate to the ISO image storage location in Proxmox.

![proxmox-iso-library](/assets/img/blog6/12-iso-library.webp)
*Figure 11: Proxmox ISO image library*

Next, upload both the Windows 11 ISO and VirtIO driver ISO files.

![uploading-iso-files-to-proxmox](/assets/img/blog6/13-iso-upload.webp)
*Figure 12: Uploading ISO files to Proxmox*

Once the upload is complete, the uploaded ISO files will appear inside the ISO image library.

![iso-upload-complete](/assets/img/blog6/14-iso-upload-complete.webp)
*Figure 13: Uploaded ISO files in the Proxmox ISO library*

## Creating the Windows 11 Virtual Machine

To create the VM, right-click the Proxmox node and select **Create VM**.

You may also notice another option called **Create CT**.

A **Virtual Machine (VM)** virtualizes an entire operating system, including its own kernel. This allows you to run operating systems such as Windows, Linux, or BSD independently.

A **Container (CT)** shares the host system's kernel while isolating applications and environments. Containers are lighter and use fewer resources, but they are generally limited to Linux-based workloads.

Since Windows requires its own kernel, we must use a virtual machine instead of a container.

![create-new-vm](/assets/img/blog6/15-create-vm.webp)
*Figure 14: Creating a new virtual machine in Proxmox*

## General Settings

In the General section, configure the following settings:

- **Node** — The physical Proxmox host server where the VM will run
- **VM ID** — A unique identifier assigned to the virtual machine
- **Name** — The display name of the VM
- **Resource Pool** — Optional grouping used to organize multiple VMs

![vm-general-configuration](/assets/img/blog6/16-select-general.webp)
*Figure 15: General VM configuration settings*

## Operating System Settings

In the OS section, select:

- The Windows 11 ISO image
- The correct storage location
- Microsoft Windows as the OS type
- The appropriate Windows version
- The VirtIO driver ISO as an additional drive

Adding the VirtIO driver ISO here is important because we will need those drivers later during the Windows installation process.

![vm-os-selection](/assets/img/blog6/17-select-os.webp)
*Figure 16: Selecting the Windows 11 and VirtIO ISO files*

## System Settings

In the System section, configure the following settings:

- **Graphic Card** — Defines the virtual display adapter presented to the VM
- **Machine** — Specifies the emulated motherboard/chipset type
- **BIOS** — Firmware interface used to boot the VM
- **EFI Storage** — Storage location for UEFI boot files
- **SCSI Controller** — Virtual disk controller used for storage devices
- **TPM** — Trusted Platform Module used for Windows 11 security requirements

### Why TPM Is Important

Windows 11 officially requires TPM 2.0 for installation. TPM is a hardware-based security feature used for functions such as:

- Secure Boot
- BitLocker encryption
- Credential protection

Proxmox can emulate TPM functionality for virtual machines, allowing Windows 11 to install successfully.

![vm-system-settings](/assets/img/blog6/18-select-system.webp)
*Figure 17: Configuring VM system settings*

## Disk Settings

In the Disk section, select:

- The storage location
- Disk size
- Cache settings

I allocated **80 GB** for the VM because it is commonly recommended for Windows 11 installations.

### Disk Cache

The **Write Back** cache mode improves disk write performance by temporarily storing writes in memory before writing them to disk. While this improves speed, it may slightly increase the risk of data loss during unexpected power failures.

![vm-disk-configuration](/assets/img/blog6/19-select-disks.webp)
*Figure 18: Configuring VM storage settings*

## CPU Settings

In the CPU section, I selected:

- **1 Socket**
- **1 Core**

### Understanding Sockets and Cores

- A **socket** represents a physical CPU
- A **core** represents an individual processing unit inside the CPU

More cores generally improve multitasking and VM performance, but they also consume more host resources.

![vm-cpu-settings](/assets/img/blog6/20-select-cpu.webp)
*Figure 19: Configuring VM CPU settings*

## Memory Settings

For memory, I allocated **4096 MB (4 GB)** of RAM.

Windows 11 can technically run with less, but 4 GB provides a smoother experience for basic usage.

![vm-memory-settings](/assets/img/blog6/21-select-memory.webp)
*Figure 20: Allocating memory to the VM*

## Network Settings

In the Network section:

- **Bridge:** vmbr0
- **VLAN Tag:** None
- **Model:** VirtIO (paravirtualized)

### Bridge Network

The bridge allows the VM to behave like a separate device on the physical network. Using `vmbr0` gives the VM direct network access through the host network adapter.

### Why Use VirtIO Networking

Using VirtIO networking improves network performance significantly compared to emulated network adapters because the VM communicates more efficiently with the hypervisor.

This reduces CPU overhead and improves throughput and latency.

![vm-network-settings](/assets/img/blog6/22-select-network.webp)
*Figure 21: Configuring VM networking settings*

After reviewing all settings in the summary page, click **Finish** to create the VM.

![vm-setup-summary](/assets/img/blog6/23-setup-summary.webp)
*Figure 22: VM configuration summary before creation*

## Loading VirtIO Storage Drivers

During the disk selection stage, Windows will not initially detect the virtual disk because the VirtIO storage driver is not yet installed.

To fix this, click **Load Driver** and then click **Browse**.

![load-virtio-storage-driver](/assets/img/blog6/26-load-drivers.webp)
*Figure 26: Loading VirtIO storage drivers*

Inside the VirtIO ISO, navigate through the folders.

You will notice folders such as:

- `2k16`
- `2k19`
- `2k22`
- `2k25`
- `w10`
- `w11`

These folders contain VirtIO drivers optimized for specific Windows versions:

- `2k16` = Windows Server 2016
- `2k19` = Windows Server 2019
- `2k22` = Windows Server 2022
- `2k25` = Windows Server 2025
- `w10` = Windows 10
- `w11` = Windows 11

In this setup, I selected the `2k25` folder.

![select-virtio-driver-folder](/assets/img/blog6/27-select-2k25.webp)
*Figure 27: Selecting the appropriate VirtIO driver folder*

Windows will now load the **Red Hat VirtIO SCSI Pass-through Controller** driver.

Once the driver appears, click **Next**.

![virtio-scsi-driver-selection](/assets/img/blog6/28-select-virtIO-drivers.webp)
*Figure 28: Selecting the VirtIO SCSI driver*

After loading the driver, the virtual disk becomes visible.

Select the **Drive 0 Unallocated Space** entry and click **Next**.

![select-installation-disk](/assets/img/blog6/29-select-installation-disk.webp)
*Figure 29: Selecting the installation disk*

Windows 11 installation will now begin.

![windows-11-installation-progress](/assets/img/blog6/30-start-installation.webp)
*Figure 30: Windows 11 installation progress*

The installer will go through several setup and configuration stages automatically.

![windows-11-final-configuration](/assets/img/blog6/31-finish-final-configs.webp)
*Figure 31: Windows 11 final setup configuration*

## Removing the Installation ISO

After installation, remove the Windows ISO from the virtual DVD drive.

This prevents the VM from booting back into the installation media during the next restart, which would otherwise cause the installer to relaunch instead of booting into the installed operating system.

![remove-installation-iso](/assets/img/blog6/32-remove-iso.webp)
*Figure 32: Removing the Windows installation ISO from the VM*

Once the installation is complete, the VM will boot into the Windows 11 login screen.

Enter the configured password to log in.

![windows-11-login-screen](/assets/img/blog6/33-installation-complete.webp)
*Figure 33: Windows 11 login screen after installation*

## Installing VirtIO Guest Tools

Although Windows is now installed, additional VirtIO drivers and guest tools are still required for optimal VM performance.

These tools improve:

- Network functionality
- Storage performance
- Memory ballooning
- VM communication with the hypervisor
- QEMU guest agent integration

Open **This PC** and navigate to the VirtIO DVD drive.

![open-virtio-cd-drive](/assets/img/blog6/34-open-virtIO-cd.webp)
*Figure 34: Opening the VirtIO driver DVD*

Run `virtio-win-guest-tools` as Administrator.

![run-virtio-guest-tools](/assets/img/blog6/35-open-virtIO-guest-tools.webp)
*Figure 35: Launching the VirtIO guest tools installer*

Continue through the installation wizard.

![virtio-tools-installation-start](/assets/img/blog6/36-tools-1.webp)
*Figure 36: Starting the VirtIO guest tools installation*

The installer will display the features included in the package.

The default installation typically includes:

- VirtIO network drivers
- VirtIO storage drivers
- Balloon drivers for memory management
- QEMU guest agent
- Additional virtualization utilities

The QEMU Guest Agent is particularly useful because it allows Proxmox to communicate with the VM more effectively for operations such as graceful shutdowns, IP reporting, and improved management functionality.

![virtio-tools-features](/assets/img/blog6/39-tools-features.webp)
*Figure 37: VirtIO guest tools installation features*

Continue with the installation.

![virtio-tools-installation-progress](/assets/img/blog6/40-tools-install.webp)
*Figure 38: Installing VirtIO guest tools*

Once the installation is complete, click **Finish**.

![virtio-tools-installation-complete](/assets/img/blog6/41-tools-install-done.webp)
*Figure 39: VirtIO guest tools installation completed*

Restart the virtual machine to apply the installed drivers and services.

## Verifying Network Connectivity

After restarting, we can verify that the VM has internet access.

Open Command Prompt and use the following command:

```powershell
ping 8.8.8.8
```

If replies are returned successfully, it confirms that the VM has working network connectivity and internet access.

![windows-11-network-connectivity-test](/assets/img/blog6/42-internet-works.webp)
*Figure 40: Verifying internet connectivity using ping*
