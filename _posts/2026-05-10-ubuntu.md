## Installing and Configuring Ubuntu VM in Proxmox

### Introduction

In my previous blog post, I went through the process of installing and configuring a Windows 11 virtual machine in Proxmox. In this blog post, I will be showing how I installed and configured an Ubuntu virtual machine inside my Proxmox homelab environment.

Ubuntu is one of the most popular Linux distributions used for servers, development environments, cybersecurity labs, containers, virtualization, and everyday computing. Running Ubuntu as a virtual machine inside Proxmox allows us to safely test Linux environments without needing separate physical hardware.

In this guide, I will go through the complete installation process step-by-step with screenshots and explain the important settings and concepts along the way so that even someone new to virtualization and Proxmox can follow along.

### Downloading the Ubuntu ISO

Before creating the virtual machine, we first need to download the Ubuntu Desktop ISO image. An ISO file is essentially a digital copy of an installation DVD that contains all the files required to install an operating system.

Ubuntu provides several download options through their official website.
You can download the Ubuntu Desktop ISO from the official Ubuntu download page below:

<https://ubuntu.com/download/alternative-downloads>

![Ubuntu ISO Download Page](/assets/img/blog7/1-iso-download-page.webp)
*Figure 1: Official Ubuntu ISO download page*

### Uploading the ISO to Proxmox

After downloading the Ubuntu ISO, the next step is to upload it into the Proxmox ISO image library.

In Proxmox, ISO images are usually stored in a dedicated storage location called an ISO image library. Keeping operating system installation media in a separate storage location helps organize files properly and allows the same ISO image to be reused across multiple virtual machines without downloading it repeatedly.

This storage area is different from the actual VM disk storage. The ISO storage only contains installation media, while the VM storage contains the virtual hard disks used by virtual machines.

To upload the ISO:

1. Open the Proxmox web interface
2. Select the local storage
3. Navigate to the **ISO Images** section
4. Click **Upload**
5. Select the downloaded Ubuntu ISO file

![Start ISO Upload](/assets/img/blog7/2-start-upload.webp)
*Figure 2: Uploading the Ubuntu ISO image into Proxmox*

Once the upload is complete, Proxmox will display a completion message and the ISO file will appear inside the ISO image library.

![ISO Upload Complete](/assets/img/blog7/3-upload-complete.webp)
*Figure 3: Ubuntu ISO upload completed successfully*

Here we can see all available ISO files stored inside the ISO image library.
Having all installation media centrally stored makes it much easier to manage multiple virtual machines in a homelab or enterprise environment.

![ISO Image Library](/assets/img/blog7/4-iso-images-library.webp)
*Figure 4: ISO image library inside Proxmox storage*

### Creating a New Virtual Machine

Now that the Ubuntu ISO is uploaded, we can begin creating the virtual machine.
To create a VM, right-click the Proxmox node and select **Create VM**.
You may also notice another option called **Create CT**.

* **VM (Virtual Machine)** virtualizes complete hardware and runs its own operating system kernel
* **CT (Container)** shares the host operating system kernel and is generally more lightweight and efficient

Virtual machines provide better isolation and compatibility, while containers are usually faster and consume fewer resources.

Since we want to install a complete Ubuntu operating system independently, we will use a virtual machine.

![Create VM](/assets/img/blog7/5-create-vm.webp)
*Figure 5: Creating a new virtual machine in Proxmox*

### General Configuration

The first page in the VM creation wizard is the **General** section.
Here we configure:

* **Node** — The physical Proxmox server where the VM will run
* **VM ID** — A unique identifier assigned to the virtual machine
* **Name** — A human-readable name for easier identification
* **Resource Pool** — Used to logically group VMs together for management purposes

I assigned a name to the VM and continued with the default VM ID.

![VM General Settings](/assets/img/blog7/6-give-vm-name.webp)
*Figure 6: Configuring the VM general settings*

### Selecting the Operating System

In the OS section, we select the Ubuntu ISO image uploaded earlier.
The options here include:

* **Storage** — Location where ISO files are stored
* **ISO Image** — The operating system installation image
* **Type** — Operating system family
* **Version** — Specific operating system version

Selecting the correct operating system type helps Proxmox optimize compatibility settings for the VM.

![Select Ubuntu ISO](/assets/img/blog7/7-select-iso-image.webp)
*Figure 7: Selecting the Ubuntu ISO image*

### Configuring System Settings

The **System** page contains several important low-level virtualization settings.

#### Graphics Card

Defines the virtual display adapter used by the VM console.

#### Machine Type

Determines the chipset and virtual hardware platform used by the VM. Modern operating systems generally work best with the default Q35 machine type.

#### BIOS

Defines the firmware interface used to boot the VM.

Modern systems typically use **UEFI BIOS**, which supports newer hardware features and secure boot functionality.

#### EFI Storage

Stores UEFI boot information required by the VM firmware.

#### SCSI Controller

Controls how storage devices communicate with the virtual machine. VirtIO SCSI provides high-performance virtualized disk access.

#### TPM

Trusted Platform Module is a virtual security chip used for security-related functions such as encryption and secure boot.
Although TPM is heavily required for Windows 11, it can also be configured for Linux virtual machines.

![System Configuration](/assets/img/blog7/8-select-system.webp)
*Figure 8: Configuring VM system settings*

### Configuring Virtual Disk Storage

Next, we configure the virtual hard disk for the VM.
This is where Ubuntu will actually be installed.
The important options here include:

#### Storage

Defines where the VM disk file will be stored.

#### Disk Size

Specifies the amount of storage allocated to the VM.
I allocated **40GB**, which is generally sufficient for a lightweight Ubuntu desktop installation.

#### Cache Mode

Controls how disk caching behaves between the guest operating system and the host.
The default **Write Back** mode can improve performance by temporarily caching writes before saving them to physical storage.

![Disk Configuration](/assets/img/blog7/9-select-disks.webp)
*Figure 9: Configuring VM virtual disk settings*

### Configuring CPU Settings

In the CPU section, we configure the virtual processors assigned to the VM.
The options include:

#### Socket

Represents a physical CPU package presented to the VM.

#### Cores

Represents the number of processing cores available to the VM.

#### Type

Defines the CPU model exposed to the guest operating system.
For this VM, I selected:

* 1 Socket
* 2 CPU Cores

This configuration is more than enough for a lightweight Ubuntu virtual machine.

![CPU Configuration](/assets/img/blog7/10-select-cpu.webp)
*Figure 10: Configuring virtual CPU settings*

### Configuring Memory

Here we allocate RAM for the virtual machine.
I assigned **2048MB (2GB)** of memory, which is sufficient for basic Ubuntu desktop usage and lightweight testing.
If you plan to run heavier applications, development tools, or multiple services, allocating additional RAM may improve performance.

![Memory Configuration](/assets/img/blog7/11-select-memory.webp)
*Figure 11: Allocating memory to the VM*

### Configuring Network Settings

The network page configures how the virtual machine connects to the network.
The selected settings include:

#### Bridge: vmbr0

`vmbr0` is the default Linux bridge interface in Proxmox.
A bridge works like a virtual network switch, allowing virtual machines to communicate with the physical network and other devices.

#### VLAN Tag

Used for VLAN segmentation.
Since I am not using VLANs in this setup, I left it empty.

#### Model: VirtIO (Paravirtualized)

VirtIO is a high-performance virtualized network driver specifically designed for virtualization environments.
Compared to emulated hardware models, VirtIO provides:

* Better performance
* Lower overhead
* Faster network throughput
* Improved efficiency

That is why VirtIO is generally recommended for Linux virtual machines.

![Network Configuration](/assets/img/blog7/12-select-network.webp)
*Figure 12: Configuring VM network settings*

### Reviewing the Configuration

Before creating the VM, Proxmox displays a summary of all selected settings.
This gives us a chance to verify the configuration before finalizing the virtual machine creation process.
If everything looks correct, click **Finish**.

![VM Summary](/assets/img/blog7/13-check-summary.webp)

### Starting the Virtual Machine

Once the VM is created, we can view all configured hardware components under the **Hardware** section.
To begin the Ubuntu installation process, click the **Start** button located in the top-right corner.

![Start VM](/assets/img/blog7/14-start-vm.webp)
*Figure 14: Starting the Ubuntu virtual machine*

### Beginning the Ubuntu Installation

After booting from the ISO image, Ubuntu presents the installation menu.
Here we can either:

* Try Ubuntu without installing
* Install Ubuntu directly

To proceed with the installation, select **Install Ubuntu**.

![Install Ubuntu](/assets/img/blog7/15-select-install.webp)
*Figure 15: Ubuntu installation menu*

### Selecting the Language

Next, select the preferred installation language.
This language will be used during the installation process and as the default system language after installation.

![Select Language](/assets/img/blog7/16-select-language.webp)
*Figure 16: Selecting the Ubuntu installation language*

### Choosing Installation Type

Ubuntu provides two installation types:

#### Normal Installation

Includes:

* Web browsers
* Office software
* Media players
* Utility applications
* Games

#### Minimal Installation

Includes:

* Basic utilities
* Web browser
* Minimal desktop environment

Since this VM will mainly be used for testing and lightweight tasks, I selected **Minimal Installation**.

![Minimal Installation](/assets/img/blog7/17-select-minimal-installation.webp)
*Figure 17: Selecting minimal Ubuntu installation*

### Selecting the Installation Disk

Earlier during VM creation, we allocated a 40GB virtual disk.
Ubuntu now detects that virtual disk as `/dev/sda`.
We simply select the disk and continue.

![Select Installation Disk](/assets/img/blog7/18-select-disk.webp)
*Figure 18: Selecting the virtual disk for Ubuntu installation*

### Writing Changes to Disk

Ubuntu will now display a confirmation screen explaining the disk changes that will occur during installation.
This step confirms that the installer will partition and format the selected virtual disk.

![Write Disk Changes](/assets/img/blog7/19-write-changes-to-disk.webp)
*Figure 19: Confirming disk write operations*

### Creating User Credentials

Next, we configure the system user account.
This includes:

* Full name
* Computer name
* Username
* Password

These credentials will be used to log into the Ubuntu system after installation.

![Ubuntu User Credentials](/assets/img/blog7/20-give-credentials.webp)
*Figure 20: Configuring Ubuntu user credentials*

### Final Installation Confirmation

Ubuntu now asks for final confirmation before erasing the selected virtual disk and installing the operating system.
Select **Erase Disk and Install Ubuntu** and continue.
Since this is a newly created virtual machine disk, erasing it is completely safe.

![Erase Disk and Install](/assets/img/blog7/21-select-erase-disk-and-install.webp)
*Figure 21: Final installation confirmation screen*

### Installing Ubuntu

Ubuntu will now begin copying files, configuring packages, and installing the operating system onto the virtual disk.
The installation process may take several minutes depending on the host hardware performance.

![Ubuntu Installation Progress](/assets/img/blog7/22-installation.webp)
*Figure 22: Ubuntu installation process in progress*

### Installation Complete

Once installation is complete, Ubuntu will prompt us to restart the virtual machine.

![Ubuntu Installation Complete](/assets/img/blog7/23-installation-complete.webp)
*Figure 23: Ubuntu installation completed successfully*

### Removing the ISO Image

Before booting back into Ubuntu, we should remove the ISO image from the virtual DVD drive.
If we leave the ISO attached, the VM may continue booting back into the installer environment instead of booting from the installed operating system on the virtual disk.
To avoid this boot loop behavior:

1. Open the VM hardware settings
2. Select the virtual CD/DVD drive
3. Remove or detach the ISO image

![Remove ISO Image](/assets/img/blog7/24-remove-disk.webp)
*Figure 24: Removing the Ubuntu ISO from the virtual DVD drive*

After removing the ISO, the VM hardware configuration should look similar to this.

![Updated Hardware Configuration](/assets/img/blog7/25-remove-disk.webp)
*Figure 25: VM hardware configuration after removing ISO image*

### Ubuntu Desktop Successfully Installed

After rebooting, the VM successfully loads into the Ubuntu desktop environment.
At this point, the Ubuntu virtual machine installation is complete.

![Ubuntu Desktop](/assets/img/blog7/26-installation-complete.webp)
*Figure 26: Ubuntu desktop environment running inside Proxmox*

### Verifying Network Connectivity

Finally, I tested internet connectivity using the `ping` command.

```bash
ping 8.8.8.8
```

This command sends ICMP echo requests to Google's public DNS server.
Receiving replies confirms that:

* The VM network configuration is working
* Internet connectivity is active
* The bridge configuration is functioning properly

![Ping Test](/assets/img/blog7/27-internet-works.webp)
