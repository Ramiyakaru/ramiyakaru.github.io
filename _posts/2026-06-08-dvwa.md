## Installing Damn Vulnerable Web Application (DVWA) on Proxmox VE Using LXC Containers

## Introduction

One of the best ways to learn cybersecurity is through hands-on practice. Reading about vulnerabilities and attack techniques is useful, but nothing replaces the experience of interacting with intentionally vulnerable systems in a controlled lab environment.

In this tutorial, we will install **Damn Vulnerable Web Application (DVWA)** inside a **Proxmox LXC container**. DVWA is one of the most popular vulnerable web applications used by cybersecurity students, penetration testers, and security professionals to practice web application security testing techniques.

By the end of this guide, you will have a fully functional DVWA instance running inside a Proxmox container that can be used to practice vulnerability assessment, penetration testing, and web security concepts safely within your own lab environment.

### What is Damn Vulnerable Web Application (DVWA)?

**Damn Vulnerable Web Application (DVWA)** is an intentionally insecure PHP/MySQL web application designed specifically for learning and practicing web application security.

DVWA contains a wide variety of common web vulnerabilities, allowing users to safely experiment with attack techniques and understand how vulnerabilities are exploited in real-world applications.

Some of the vulnerabilities included in DVWA are:

* SQL Injection (SQLi)
* Cross-Site Scripting (XSS)
* Command Injection
* File Inclusion Vulnerabilities
* Cross-Site Request Forgery (CSRF)
* File Upload Vulnerabilities
* Authentication Bypass
* Brute Force Attacks
* Insecure CAPTCHA Implementations
* Weak Session Management

Unlike production applications, DVWA intentionally contains these vulnerabilities to provide a safe environment for learning.

### Why DVWA is an Excellent Platform for Learning Cybersecurity

DVWA is widely used in cybersecurity education because it offers several advantages:

#### Safe Learning Environment

Instead of testing techniques against real systems, which may be illegal or unethical, DVWA provides a controlled environment specifically built for experimentation.

#### Multiple Difficulty Levels

DVWA allows vulnerabilities to be configured at different security levels:

* Low
* Medium
* High
* Impossible

This allows learners to gradually increase the challenge level as their skills improve.

### Practice with Real Security Tools

DVWA can be used with industry-standard tools such as:

* Burp Suite
* OWASP ZAP
* Nikto
* SQLMap
* Hydra
* Nmap
* Metasploit Framework

### Understand How Vulnerabilities Work

Rather than simply reading about attacks, DVWA lets users:

* Discover vulnerabilities
* Exploit vulnerabilities
* Understand the impact
* Learn mitigation techniques

This practical approach significantly improves learning retention.

### Understanding Proxmox Containers

Before deploying DVWA, it is important to understand the technology being used to host it.

In this tutorial, we are using a **Proxmox LXC Container** rather than a traditional virtual machine.

### What is a Container?

A container is a lightweight virtualization technology that allows applications and services to run in isolated environments while sharing the host system's operating system kernel.

Think of a container as a separate mini-computer that has:

* Its own filesystem
* Its own users
* Its own processes
* Its own network stack

However, unlike a virtual machine, it does not require its own operating system kernel.

This makes containers significantly more efficient.

### Container Architecture

```text
+-----------------------------------+
| Physical Server                   |
+-----------------------------------+
| Proxmox VE                        |
+-----------------------------------+
| Linux Kernel (Shared)             |
+-----------------------------------+
| Container 1                       |
| Container 2                       |
| Container 3                       |
+-----------------------------------+
```

All containers share the same Linux kernel while remaining isolated from each other.

### Containers vs Virtual Machines

### Virtual Machines

A virtual machine emulates an entire computer.

```text
+---------------------+
| Application         |
+---------------------+
| Guest OS            |
+---------------------+
| Virtual Hardware    |
+---------------------+
| Hypervisor          |
+---------------------+
| Physical Hardware   |
+---------------------+
```

Each VM includes:

* Full operating system
* Virtual CPU
* Virtual memory
* Virtual storage
* Virtual network adapters

#### Advantages

* Strong isolation
* Can run different operating systems
* Excellent for malware analysis

#### Disadvantages

* Higher resource usage
* Larger storage requirements
* Slower startup times

### Containers

Containers share the host operating system kernel.

```text
+---------------------+
| Application         |
+---------------------+
| Container Runtime   |
+---------------------+
| Shared Linux Kernel |
+---------------------+
| Physical Hardware   |
+---------------------+
```

#### Advantages

* Extremely lightweight
* Fast startup
* Low resource usage
* Easy deployment

#### Disadvantages

* Must use Linux-compatible workloads
* Less isolation than a VM

### When Should You Use Containers?

Containers are ideal when:

* Hosting web applications
* Running development environments
* Deploying lab services
* Running Docker workloads
* Hosting databases
* Testing applications

Examples include:

* DVWA
* OWASP Juice Shop
* GitLab
* Jenkins
* Nginx
* WordPress

### Why Use a Container for DVWA Instead of a Virtual Machine?

DVWA is a lightweight web application.

It does not require:

* A dedicated kernel
* Large amounts of RAM
* Multiple CPU cores

Using a container provides several benefits:

#### Lower Resource Usage

A container running DVWA can comfortably operate with:

* 1 CPU Core
* 512 MB RAM
* 8 GB Storage

A virtual machine would typically require significantly more resources.

#### Faster Deployment

Containers can be created and started within minutes.

#### Better Lab Density

Because containers consume fewer resources, a single Proxmox server can host many vulnerable applications simultaneously.

For example:

* DVWA
* OWASP Juice Shop
* Metasploitable 2
* Metasploitable 3
* Security Monitoring Tools

all on the same hardware.

### What is Nesting?

Nesting allows a container to run container-related technologies and services that would otherwise be restricted.
Some applications expect functionality normally available only in a full Linux environment.
Enabling nesting improves compatibility and avoids permission-related issues during installation and operation.

Although DVWA itself does not strictly require nesting, enabling it is considered good practice for cybersecurity lab containers and provides additional flexibility if Docker or other containerized services are later installed.

## Step 4 – Install Required Packages

Update the system and install required software.

Update the package list and upgrade system packages

```bash
apt update && apt upgrade -y
```

Install git and unzip

```bash
apt install git unzip -y
```

Install Apache, MariaDB (MySQL), and PHP modules required by DVWA

```bash
apt install apache2 mariadb-server php php-mysqli php-gd libapache2-mod-php -y
```

### Step 5 – Download DVWA

Navigate to Apache's web root and clone DVWA repo from Digininja.

```bash
cd /var/www/html
git clone https://github.com/digininja/DVWA.git dvwa
```

### Step 6 – Configure Permissions

Grant Apache ownership of the application files.

```bash
chown -R www-data:www-data /var/www/html/dvwa
chmod -R 755 /var/www/html/dvwa
```

### Step 7 – Configure DVWA

Navigate to the DVWA configuration directory.

```bash
cd /var/www/html/dvwa/config
cp config.inc.php.dist config.inc.php
```

Open the configuration file.

```bash
nano config.inc.php
```

![DVWA configuration file](/assets/img/blog12/7-dvwa-config.webp)
*Figure 7: Reviewing DVWA database configuration settings.*

By default, DVWA expects:

```php
$_DVWA['db_user'] = 'dvwa';
$_DVWA['db_password'] = 'password';
```

or

```php
$_DVWA['db_user'] = 'dvwa';
$_DVWA['db_password'] = 'p@ssw0rd';
```

For a local cybersecurity lab, these values can remain unchanged. Make sure you note down the password as we need it later.
Save and exit the editor.

### Step 8 – Configure MariaDB for Proxmox Containers

Open a systemd override configuration.

```bash
systemctl edit mariadb
```

![MariaDB service override configuration](/assets/img/blog12/8-mariadb-config.webp)
*Figure 8: Creating a MariaDB systemd override configuration.*

Add the following configurations to the top of the text file:

```ini
[Service]
ProtectSystem=false
ProtectHome=false
PrivateTmp=false
ProtectHostname=false
ProtectKernelTunables=false
ProtectKernelModules=false
ProtectControlGroups=false
RestrictRealtime=false
ReadWritePaths=
```

Save and exit.
Reload systemd:

```bash
systemctl daemon-reload
```

Check MariaDB status:

```bash
systemctl status mariadb
```

If MariaDB is not running:

```bash
systemctl enable mariadb
systemctl start mariadb
```

Verify again:

```bash
systemctl status mariadb
```

The service should show:

```text
active (running)
```

### Step 9 – Create the DVWA Database

Access MariaDB:

```bash
mysql -u root
```

Create the database and user and here enter the same password we noted down earlier.

![Creating the DVWA database](/assets/img/blog12/9-dvwa-db-config.webp)
*Figure 9: Creating the DVWA database and user account.*

```sql
CREATE DATABASE dvwa;
CREATE USER 'dvwa'@'localhost' IDENTIFIED BY 'password';
GRANT ALL PRIVILEGES ON dvwa.* TO 'dvwa'@'localhost';
FLUSH PRIVILEGES;
EXIT;
```

### Step 10 – Enable Required PHP Features

DVWA requires the PHP setting:

```text
allow_url_include
```

to be enabled for testing file inclusion vulnerabilities.

Open the PHP configuration file.

```bash
nano /etc/php/8.*/apache2/php.ini
```

![Editing PHP configuration](/assets/img/blog12/10-apache2-config.webp)
*Figure 10: Enabling required PHP settings for DVWA.*

### Tip for Proxmox Console Users

Sometimes **Ctrl+W** closes the browser tab instead of searching within Nano.

To make navigation easier:

```bash
nano -l /etc/php/8.*/apache2/php.ini
```

This opens Nano with line numbers enabled.

Scroll to approximately:

```text
Lines 850–870
```

Locate:

```ini
allow_url_include = Off
```

Change it to:

```ini
allow_url_include = On
```

Save and exit.

Restart Apache:

```bash
systemctl restart apache2
```

Find the container IP address.

```bash

```

### Security Considerations

DVWA is intentionally vulnerable.

Never expose a DVWA instance to:

* The public internet
* Port forwarding
* Cloud-hosted production environments

Always keep DVWA isolated within:

* A home lab
* A virtual lab network
* A cybersecurity training environment

Consider placing DVWA on a dedicated VLAN or isolated subnet when building larger penetration testing labs.

## Conclusion

Damn Vulnerable Web Application remains one of the most valuable platforms for learning web application security. By deploying DVWA inside a Proxmox LXC container, we gain a lightweight, efficient, and easily manageable training environment that consumes minimal resources while still providing a realistic platform for practicing offensive security techniques.

Throughout this tutorial, we created a Debian-based LXC container, installed Apache, MariaDB, PHP, and DVWA, configured the required services, enabled vulnerable PHP features, and initialized the application database. The result is a fully functional web security training platform that can be used with tools such as Burp Suite, OWASP ZAP, SQLMap, Hydra, Nikto, and Metasploit.

In future lab exercises, this DVWA instance can be used to explore topics such as SQL Injection, Cross-Site Scripting (XSS), File Inclusion vulnerabilities, authentication weaknesses, session management flaws, and many other common web application security issues. Combined with other intentionally vulnerable systems such as Metasploitable and OWASP Juice Shop, DVWA forms an essential component of any cybersecurity home lab.
