## Installing and Configuring Windows Server 2022 on Proxmox VE

Virtualization has become a core technology in modern IT environments, from enterprise datacenters to personal homelabs. One of the most powerful open-source virtualization platforms available today is Proxmox VE. In this guide, I will walk through the complete process I followed to install and configure Windows Server 2022 inside Proxmox.

This article is designed for beginners who are just starting with virtualization and homelab technologies. I will explain each configuration step, why certain settings matter, and how Proxmox interacts with virtual machines behind the scenes.

By the end of this guide, you will have a fully working Windows Server 2022 virtual machine running inside Proxmox VE with optimized VirtIO drivers installed for better performance.

## What is VirtIO?

VirtIO drivers are specialized **paravirtualized drivers** used in virtual machines.

### What is Paravirtualization?

Paravirtualization is a virtualization technique where the guest operating system is aware that it is running inside a virtualized environment. Instead of emulating real physical hardware devices, the hypervisor provides optimized virtual devices specifically designed for virtualization.

This allows the virtual machine to communicate more efficiently with the host system.

Without VirtIO drivers, Windows would use slower emulated hardware such as standard IDE disk controllers or legacy network adapters. While these emulated devices improve compatibility, they introduce additional overhead and reduce performance.

VirtIO drivers significantly improve:

- Disk performance
- Network throughput
- Resource efficiency
- VM responsiveness
- CPU utilization

In Proxmox, VirtIO is commonly used for:

- Virtual disks
- Network adapters
- Memory ballooning
- Guest agent communication

Because Windows does not include VirtIO drivers by default, we must manually provide them during installation.

## Why Store ISOs in a Dedicated ISO Library?

Proxmox organizes storage into different content types such as:

- ISO images
- VM disks
- Containers
- Backups
- Snippets

Separating ISO files from VM disks improves storage organization and management.
ISO images are read-only installation media, while VM disks are writable virtual storage devices that continuously change during operation. Keeping them separated helps:

- Simplify storage management
- Improve organization
- Reduce accidental deletion
- Make backups easier
- Allow ISO reuse across multiple VMs

Typically, Proxmox stores uploaded ISOs under local storage configured specifically for ISO images.

## Creating a New Virtual Machine

To create a new virtual machine, right-click the Proxmox node and select **Create VM**.

![creating vm](/assets/img/blog4/5-create-vm.webp)
*Figure 5: Creating Virtual machine*

You may also notice another option called **Create CT**.

## Virtual Machine vs Container

### Virtual Machine (VM)

A virtual machine emulates an entire computer system including:

- Virtual CPU
- Virtual memory
- Virtual disks
- Virtual network hardware

Each VM runs its own independent operating system kernel.
Examples:

- Windows Server
- Ubuntu Server
- Kali Linux

### Container (CT)

Containers are more lightweight and share the host system kernel instead of emulating full hardware.
Containers:

- Start faster
- Use fewer resources
- Have lower overhead

However, containers cannot run a different kernel than the host. Since Proxmox uses a Linux kernel, Windows cannot run inside a container.
That is why we must use a full virtual machine for Windows Server 2022.

## General VM Configuration

The first page in the VM creation wizard is the **General** section.

![setup general page](/assets/img/blog4/6-setup-general.webp)
*Figure 6: General page of vm create process*

Here we configure:

- Node
- VM ID
- Name
- Resource Pool

## Node

A node refers to an individual Proxmox server participating in the virtualization environment.
In a single homelab setup, your Proxmox server itself is the node.

## VM ID

Every virtual machine in Proxmox receives a unique numerical identifier.
This ID helps Proxmox internally manage:

- VM configurations
- Storage allocation
- Networking
- Backups

## Resource Pool

Resource pools are used to logically group VMs and containers together.
This is especially useful in enterprise environments for:

- Department separation
- Permission management
- Resource organization

For a small homelab, this can usually remain as the default setting.

## Operating System Configuration

Next is the **OS** page.

![setup os page](/assets/img/blog4/7-setup-os.webp)
*Figure 7: Operating System page of vm create process*

Here we select:

- Storage location

- Additional driver ISO

## System Configuration

The next section is the **System** page.

![setup system page](/assets/img/blog4/8-setup-system.webp)
*Figure 8: System page of vm create process*

Several important virtualization settings are configured here.

## Graphics Card

This determines the virtual display adapter used by the VM console.
For most server installations, the default option works perfectly.

## Machine Type

The machine type defines the virtual chipset and hardware platform presented to the guest operating system.
Modern Proxmox installations typically use **q35**, which supports newer PCIe-based virtual hardware.

## BIOS

The BIOS option determines the firmware interface used to boot the VM.
Modern systems commonly use:

- SeaBIOS (legacy BIOS)
- OVMF (UEFI firmware)

UEFI is recommended for newer operating systems such as Windows Server 2022.

## EFI Storage

EFI storage stores UEFI-related boot files and firmware variables for the VM.
Using the same local storage is perfectly acceptable in most homelab environments.

## SCSI Controller

The SCSI controller manages communication between the VM and virtual storage devices.
Using the VirtIO SCSI controller provides:

- Better disk performance
- Lower overhead
- Improved virtualization efficiency

## TPM

TPM stands for **Trusted Platform Module**.
It is a virtualized security chip used for:

- Secure boot
- Encryption
- Credential protection

Newer Windows operating systems increasingly rely on TPM functionality.

## Disk Configuration

Next is the **Disks** page.

![setup disks page](/assets/img/blog4/9-setup-disks.webp)
*Figure 9: Disk allocation page of vm create process*

Here we configure:

- Storage location
- Disk size
- Cache mode

## Storage Location

This determines where the VM’s virtual disk will physically reside on the Proxmox host.
Depending on your setup, this could be:

- NVMe SSD
- SATA SSD
- HDD
- ZFS storage pool
- LVM-thin storage

## Disk Capacity

By default, Proxmox suggests 32GB.
For basic testing and learning purposes, 32GB is generally sufficient for Windows Server 2022.
However, production workloads typically require significantly more storage.

## Cache Mode

Cache mode affects how disk writes are handled between the guest OS and the host system.
The default **Write Back** mode improves performance by temporarily caching writes in host memory before committing them to disk.
This increases speed but may introduce minor data loss risk during unexpected power failure if no UPS is present.

## CPU Configuration

The next page configures the virtual CPU.

![setup cpu page](/assets/img/blog4/10-setup-cpu.webp)
*Figure 10: CPU allocation page of vm create process*

In this setup:

- 1 Socket
- 2 Cores

## CPU Sockets

Sockets represent virtual physical CPU packages.

## CPU Cores

Cores represent the number of processing units assigned to the VM.
For lightweight Windows Server lab environments, 2 cores is usually sufficient.

## CPU Type

The CPU type determines which CPU features are exposed to the guest operating system.
Using the default or host type typically provides the best compatibility and performance.

## Memory Configuration

Next is the **Memory** page.

![setup memory page](/assets/img/blog4/11-setup-memory.webp)
*Figurer 11: Memory (RAM) allocation page of vm create process*

For this VM, I allocated:

- 4096MB (4GB) RAM

Windows Server 2022 can technically run with less memory, but 4GB provides a much smoother experience for lab testing and administrative tasks.

## Network Configuration

The next section is the **Network** page.

![setup network page](/assets/img/blog4/12-setup-network.webp)
*Figure 12: Network configuration page of vm create process*

Here we configure:

- Bridge
- VLAN tag
- Network model

## Bridge (vmbr0)

`vmbr0` is the default Linux bridge created by Proxmox.

A network bridge acts like a virtual switch, allowing virtual machines to communicate with:

- The host machine
- Other VMs
- The physical network
- The internet

## VLAN Tag

VLAN tags are used to logically separate network traffic.
Since this VM is being placed on the default network, no VLAN tag is used here.

## Network Model — VirtIO (Paravirtualized)

We select **VirtIO (paravirtualized)** because it provides significantly better network performance compared to emulated adapters such as Intel E1000.

Benefits include:

- Lower CPU overhead
- Faster throughput
- Better virtualization efficiency
- Reduced latency

Again, Windows does not include these drivers natively, which is why we later install the VirtIO driver package.

## Standard vs Datacenter

### Standard Edition

Designed for smaller environments and general-purpose server workloads.

### Datacenter Edition

Includes advanced enterprise features such as:

- Software-defined networking
- Storage Spaces Direct
- Shielded VMs
- Advanced virtualization rights

For homelab learning, Standard Edition is usually more than sufficient.

## Desktop Experience vs Server Core

### Desktop Experience

Includes the traditional graphical user interface (GUI).
This is much easier for beginners.

### Server Core

A minimal installation without the graphical desktop environment.
Benefits include:

- Reduced resource usage
- Smaller attack surface
- Improved security

However, Server Core relies heavily on command-line and PowerShell administration.
For learning purposes, Desktop Experience is the better choice.
