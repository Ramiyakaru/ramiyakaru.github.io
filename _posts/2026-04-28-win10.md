## Installing and Configuring Windows 10 on Proxmox VE

This is my fifth blog post in my homelab and virtualization journey. In my previous post, I covered how I installed and configured Windows Server 2022 as a virtual machine in Proxmox VE. In this article, I will walk through the complete process of installing and configuring a Windows 10 virtual machine in Proxmox VE.

This guide is written with beginners in mind, so I will explain the important concepts along the way, including virtualization basics, VirtIO drivers, VM configuration settings, and networking. I will also include screenshots for every major step so it is easier to follow along.

## What is Proxmox VE?

Before starting the installation, it is important to understand what Proxmox VE is.

Proxmox Virtual Environment (Proxmox VE) is an open-source virtualization platform that allows users to create and manage virtual machines (VMs) and containers from a centralized web interface. It is widely used in homelabs, enterprise environments, and cybersecurity labs because it is lightweight, powerful, and easy to manage.

With Proxmox, a single physical machine can run multiple operating systems simultaneously, each isolated inside its own virtual environment.

## Downloading the VirtIO Drivers

Next, we need to download the VirtIO driver ISO.

VirtIO drivers are specialized **paravirtualized drivers** designed for virtual machines. To understand this better, we first need to briefly understand paravirtualization.

## What is Paravirtualization?

Normally, a virtual machine communicates with emulated hardware devices created by the hypervisor. While this works well, emulated hardware can be slower because the hypervisor must imitate physical devices.

Paravirtualization improves performance by allowing the guest operating system to communicate more directly with the hypervisor using optimized virtual drivers instead of fully emulated hardware.

This provides several benefits:

- Faster disk performance
- Better network throughput
- Lower CPU overhead
- Improved overall VM responsiveness

Without VirtIO drivers, Windows may not detect virtual disks or network adapters correctly during installation.

You can download the VirtIO drivers from:

<https://fedorapeople.org/groups/virt/virtio-win/direct-downloads/archive-virtio/virtio-win-0.1.262-2/>

![Create VM Option](/assets/img/blog5/14-create-vm.webp)
*Figure 14: Creating a new virtual machine in Proxmox*

## Virtual Machine vs Container

### Virtual Machine (VM)

A virtual machine emulates a complete computer system, including its own kernel and operating system. VMs provide strong isolation and can run completely different operating systems from the host.

### Container (CT)

Containers share the host operating system kernel while isolating applications and services. They are lightweight and use fewer resources than VMs.

### Main Differences

| Feature | Virtual Machine | Container |
|---|---|---|
| Has own OS kernel | Yes | No |
| Resource usage | Higher | Lower |
| Isolation | Stronger | Lightweight |
| Boot speed | Slower | Faster |
| Best use case | Full operating systems | Lightweight services |

Since Windows requires its own kernel, we must use a virtual machine instead of a container.

## System Configuration

The next page is the **System** configuration page.

![System Configuration](/assets/img/blog5/17-select-system.webp)
*Figure 17: Configuring VM system settings*

### Understanding these Options

### Graphics Card

Defines the virtual display adapter presented to the VM.

### Machine Type

Determines the virtual motherboard and chipset used by the VM.

### BIOS

Controls the VM firmware interface. Modern operating systems generally use UEFI.

### EFI Storage

Stores UEFI boot information for the VM.

### SCSI Controller

Handles communication between the VM and virtual storage devices. VirtIO SCSI provides better performance.

### TPM

Trusted Platform Module support used for modern Windows security features such as BitLocker and secure boot operations.

## Disk Configuration

The disk configuration page allows us to define the virtual hard drive settings.

I allocated:

- 80GB disk size
- Write back cache (default)

![Disk Configuration](/assets/img/blog5/18-select-disks.webp)
*Figure 18: Configuring the VM virtual disk*

### Understanding the Options

### Storage Location

Determines where the VM disk file will be stored on the Proxmox host.

### Disk Size

Defines the maximum capacity of the virtual disk.

### Cache Mode

The cache setting controls how disk write operations are handled between the VM and physical storage.

**Write back** caching improves performance by temporarily storing write operations in memory before writing them to disk.

## CPU Configuration

Next is the CPU configuration page.

For this setup:

- 1 Socket
- 1 Core

![CPU Configuration](/assets/img/blog5/19-select-cpu.webp)
*Figure 19: Configuring VM CPU settings*

## Understanding CPU Options

### Socket

Represents a physical CPU package.

### Core

Represents processing cores assigned to the VM.

Increasing cores generally improves multitasking and VM performance, but also consumes more host resources.

## Memory Configuration

For memory allocation, I assigned **4096MB (4GB)** of RAM.

![Memory Configuration](/assets/img/blog5/20-select-memory.webp)
*Figure 20: Allocating memory to the VM*

## Network Configuration

Next is the network configuration page.

I selected:

- Bridge: `vmbr0`
- VLAN Tag: None
- Model: VirtIO (paravirtualized)

![Network Configuration](/assets/img/blog5/21-select-network.webp)
*Figure 21: Configuring virtual network settings*

## Understanding these options

### Bridge (vmbr0)

A bridge acts like a virtual network switch that connects the VM to the physical network.

### VLAN Tag

Used to separate network traffic into different virtual LANs.

### VirtIO Network Model

The VirtIO network adapter provides significantly better network performance compared to fully emulated adapters because it uses paravirtualized drivers optimized for virtualization environments.

## Final Thoughts

Installing Windows 10 on Proxmox VE is a relatively straightforward process once the basic virtualization concepts are understood. The most important step is correctly loading the VirtIO drivers during installation, since Windows does not natively include them.

Using VirtIO drivers significantly improves VM performance by reducing the overhead caused by fully emulated hardware devices. Combined with Proxmox VE, this creates a fast, flexible, and efficient virtualization environment suitable for homelabs, testing environments, cybersecurity labs, and learning platforms.

This setup can now be used for:

- Software testing
- Lab environments
- Active Directory practice
- Networking experiments
- Cybersecurity training
- Development environments
